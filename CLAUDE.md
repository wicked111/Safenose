## Project Overview

**Safenose** is a Kotlin Multiplatform (KMP) fragrance discovery and rating app targeting Android and iOS.

## Build Commands

```bash
# Build everything
./gradlew build

# Assemble Android APK
./gradlew :composeApp:assembleDebug

# Run all tests
./gradlew test

# Run tests for a specific module
./gradlew :shared:test
./gradlew :composeApp:test

# Run a single test class
./gradlew :shared:test --tests "org.wickedtools.safenose.YourTestClass"

# iOS: open Xcode project then build/run from Xcode
open iosApp/iosApp.xcodeproj
```

## Module Architecture

Two Gradle modules:

- **`shared`** — Multiplatform (Android + iOS). Contains all business logic, data layer, and DI setup. Compiled to a static framework for iOS.
- **`composeApp`** — Android-only presentation layer. Contains all Compose screens, components, and Android entry point (`MainActivity`).

## Code Architecture

**Pattern:** Clean Architecture with feature-based modules.

**Layer structure within each feature** (under `shared/src/commonMain/kotlin/org/wickedtools/safenose/`):
```
feature_<name>/
  data/          # Repository implementations, DTOs, remote data sources
  domain/        # Interfaces (repositories), models, use cases
  presentation/  # ViewModels
  di/            # Koin module for the feature
```

**Core infrastructure** (in `shared`):
- `core/data/remote/SupabaseClient.kt` — Supabase client singleton (PostgREST + Auth)
- `core/di/CoreModule.kt` — Provides Supabase client to Koin
- `core/domain/model/` — Shared domain models (e.g., `User`)
- `di_main/Koin.kt` — `initKoin()` entry point, called from Android `MainActivity` and iOS app startup

**Dependency Injection:** Koin. Each feature exposes its own Koin module; all are aggregated in `di_main/Koin.kt`.

**Backend:** Supabase (`https://uhrobxsuehjmjypudfrn.supabase.co`) using `postgrest-kt` and `auth-kt`.

## Product Vision & Core Differentiators

**The Problem Safenose Solves:** Fragrantica reviews are useless for Indian users because longevity/sillage ratings from London or New York don't translate to Indian weather (heat, humidity, monsoon). A review has no context without knowing where the reviewer is from.

**The Killer Feature:** Every review is tied to the user's **city**. When signing up, users must enter their city. On every review card, the reviewer's city is displayed prominently (e.g., "Rohan, Mumbai"). This lets readers immediately understand the climatic context of any review.

**Target Audience:** Indian fragrance enthusiasts (ages 18–45), from beginners to collectors. Growing "desi fragrance community" on FB groups (Fragrance Addicts India), Reddit (r/DesiFragranceAddicts), and YouTube.

**App Name:** Safenose. It is a **startup** — not just an app.

## Dual Rating System

Every fragrance has two distinct rating types:

### 1. User Rating (Subjective)
- Overall personal experience
- Format: **1–5 stars**

### 2. Safenose Rating (Objective Performance)
- Three individual components, each graded **S / A / B / C** (S = best, C = worst):
  - **Longevity** — how long the scent lasts
  - **Projection** — how far it projects (sillage)
  - **Value for Money** — cost-to-performance ratio
- Combined into a **3-letter code**: e.g., `SSS`, `SAS`, `ABC`
- Only store the individual S/A/B/C grades in the database; compose the display string in the ViewModel/UI

## Database (Supabase)

**Project URL:** `https://uhrobxsuehjmjypudfrn.supabase.co`

### `brands` table
```sql
CREATE TABLE public.brands (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  name TEXT NOT NULL,
  country_of_origin TEXT,
  is_indian_brand BOOLEAN DEFAULT FALSE,
  logo_url TEXT
);
```

### `fragrances` table
```sql
CREATE TABLE public.fragrances (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  name TEXT NOT NULL,
  concentration TEXT,       -- EDT, EDP, Parfum, etc.
  launch_year INT,
  image_url TEXT,
  top_notes TEXT,           -- comma-separated string (MVP simplification)
  middle_notes TEXT,
  base_notes TEXT,
  brand_id BIGINT NOT NULL,
  CONSTRAINT fk_brand FOREIGN KEY(brand_id) REFERENCES public.brands(id) ON DELETE CASCADE
);
```

### `profiles` table (public, linked to auth.users)
```sql
CREATE TABLE public.profiles (
  id UUID PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  updated_at TIMESTAMPTZ,
  username TEXT UNIQUE,
  full_name TEXT,
  avatar_url TEXT,
  city TEXT NOT NULL,   -- THE CORE FEATURE
  state TEXT,
  CONSTRAINT username_length CHECK (char_length(username) >= 3)
);
```

### `reviews` table
```sql
CREATE TABLE public.reviews (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  review_text TEXT,
  rating SMALLINT CHECK (rating >= 1 AND rating <= 5),   -- user star rating
  longevity_rank TEXT,      -- S, A, B, or C
  projection_rank TEXT,     -- S, A, B, or C
  value_rank TEXT,          -- S, A, B, or C
  season_worn TEXT,         -- Summer, Monsoon, Winter
  user_id UUID NOT NULL REFERENCES public.profiles(id) ON DELETE CASCADE,
  fragrance_id BIGINT NOT NULL REFERENCES public.fragrances(id) ON DELETE CASCADE,
  CONSTRAINT unique_user_fragrance_review UNIQUE (user_id, fragrance_id)
);
```

**Data population:** ~2000 fragrances pre-loaded from Google Sheets CSV. Fragrance images sourced from a RapidAPI fragrance API (`fragrance-api.p.rapidapi.com`) — used for initial seeding only. Images are uploaded to Supabase Storage; only the URL is stored in `image_url`. Do NOT hotlink from external CDNs.

## Feature Module Structure (`shared/src/commonMain/kotlin/org/wickedtools/safenose/`)

```
core/
  data/remote/SupabaseClient.kt     # Supabase singleton
  di/CoreModule.kt                  # Koin: provides SupabaseClient as single{}
  domain/model/User.kt              # Shared across features

di_main/Koin.kt                     # initKoin() — aggregates all modules

feature_authentication/             # Signup/login/session
feature_fragrance/                  # Fetch & display fragrance data
feature_reviews/                    # Write & read reviews
feature_userrating/                 # 1–5 star user rating
feature_safenoserating/             # S/A/B/C Longevity/Projection/Value rating
feature_profile/                    # View & edit user profile
feature_like/                       # Like/favorite fragrances & reviews
feature_complementbox/              # Log compliments received while wearing
feature_search/                     # Search fragrances/brands
feature_share/                      # Share to other apps
```

Each feature follows: `data/ domain/ presentation/ di/`

**DI pattern:** `single<Interface> { ImplementationClass(get()) }` — never use `.bind()`. The `core/di/CoreModule.kt` provides the SupabaseClient as a singleton; every feature's data repository receives it via constructor injection.

## Android UI (`composeApp`)

- **Language/Framework:** Jetpack Compose (Material 3)
- **Navigation:** Simple `var currentScreen by remember { mutableStateOf(Screen.Home) }` + `when` block in `App.kt` — no Jetpack Navigation library yet
- **Image loading:** Coil (`coil.compose.AsyncImage` for URLs, `Image` + `painterResource` for local assets)
- **Key screens built so far:** HomeScreen (TopAppBar + SearchBar + BottomNav), ReviewCard component, RatingBar component
- **BottomNav tabs:** Home | Add Review | Profile (3 tabs)
- **Color resource:** `R.color.primary` used for TopAppBar background

### Splash Screen
- 2-second artificial delay via `installSplashScreen().apply { setKeepOnScreenCondition { elapsed <= 2000 } }`
- Logo: complex SVG vector in `drawable/` — wrapped in `<inset android:inset="30dp">` drawable to prevent circular-mask cropping
